# 相同显式槽位下的最新反馈字典基线

无需重训或模型前向：重放既有text_runtime/stream96.json，给字典与模型完全相同的调用方entity slot、已到达feedback（含错误反馈）、update-recency容量淘汰和probe时刻。

```bash
python -m evaluation.explicit_slot_baseline
python -m unittest tests.test_explicit_slot_baseline -v
```

## 目的

前述文本Runtime使用外部slot ledger。因此必须比较一个直接查询该ledger的普通字典，而不能将神经矩阵读出高分直接当架构优势。

字典不识别中文、不提取实体。给它显式entity ID，是与既有模型会话相同的强接口辅助；模型仍处理中文问句，故这只是明确slot接口下的系统基线，不是独立NLP benchmark。

## 三seed描述结果

| 策略 | 沿流最新truth平均正确率 | 最终正确率 | micro覆盖 | 接受项precision |
|---|---:|---:|---:|---:|
| 最新值字典/全部8 key | 98.17% | 100% | 100% | 98.96% |
| 最新值字典/容量4 | 53.55% | 50% | 52.85% | 98.03% |
| 最新值字典/容量8 | 98.17% | 100% | 100% | 98.96% |
| 矩阵M/外部ledger4重建 | 59.63% | 50% | 未设置拒答 | 不适用 |
| 矩阵M/外部ledger8重建 | 96.48% | 95.83% | 未设置拒答 | 不适用 |
| 矩阵M/无覆盖累加 | 41.25% | 45.83% | 未设置拒答 | 不适用 |

表中沿流正确率是每事件全部已见key的accuracy再平均；coverage/precision先在每个seed内按全部probe计算micro指标，再对3seed平均（不是合并全部seed的pooled比率），所以不是同一个分母。三seed均值只是描述，无显著性宣称。

## 解释

- 8槽位精确字典高于矩阵M，说明这个任务的正确状态管理可由简单算法完成；当前没有PBSLM记忆优于普通检索的证据。
- 字典在错误反馈到达后同样会存错，直到纠正反馈到达；它不获知隐藏truth，所以不是事实验证器。
- 容量4字典对被淘汰项明确abstain，并在all-probe正确率中算错；矩阵模型对所有项输出预测，可能凭干扰残余/猜测得到额外正确，但也可能误导。不能据59.63%>53.55%宣布矩阵更可靠。
- 字典每事件一次普通映射更新，矩阵ledger重建需要多次神经写入；存储字节/FLOPs未严格profile，不称等资源优势。
- 原JSON无改动，exact slot顺序与原bounded arm每事件核对相同。结果保留逐probe答案/abstain/target，可重算。

## 研究决策

后续必须将“任务需要语义泛化/软匹配”与“精确slot覆盖”分开。精确槽位优先保留可审计字典作为强基线；只有在未知表面、噪声、模糊实体或压缩预算下神经读出带来可测益处，才能支持其额外复杂度。不能用通用目标的远景回避这个简单基线。
