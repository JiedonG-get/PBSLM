# 目标—属性注意力：简单机制测试

本次按用户要求只做简单测试，无训练、不改PBSLM、不下载模型。复用标准cosine attention；不是新注意力算法成绩。

```bash
python -m evaluation.query_attribute_attention_smoke
python -m unittest tests.test_query_attribute_attention tests.test_segmented_working_read -v
```

## 人工定义的任务

8个对象×3属性，每对象3个值不同，从8类中随机抽取。键为对象onehot与属性onehot拼接，值为类别onehot；query使用同样的显式对象/属性编码。3seed共72次查询，温度.1预先固定。

属性只用抽象ID，不把不同物理单位强行当同一种语义。模型无需学会编码、属性识别、目标推断或语言处理。故正结果主要是构造与实现一致性检查。

## 实际结果

| 读法/条件 | 正确数 |
|---|---:|
| 对象＋属性query | 72/72 |
| 只有对象，属性清零 | 24/72 |
| 只有属性，对象清零 | 30/72 |
| 随机重排记录，完整query | 72/72 |
| 显式替换一条属性值后 | 72/72 |
| 为对象0的3个query增加其他对象记录的4份重复 | 9/9 |

只对象时3属性键同分，本任务每对象属性值互异，读取会混合，不能定位属性；不是训练失败或随机chance基准。只属性可混入其他对象值，偶然匹配不能证明选对对象。

替换由测试代码显式指定记录，其他value记录bitwise不变；没有学习更新门控，也没有验证其他query的连续输出向量完全不变（这里只保证最终分类一致）。无关记录只有固定重复次数，更多重复可能改变softmax总质量，不保证任意数量鲁棒。

## 保留的反例

若不移除旧记录，而是加入与旧键完全相同、值矛盾的新记录，两个值都获得大于.4的输出分量。普通相关性注意力无法从这个输入决定哪条更新、可信或有效；不能把softmax当纠错或真值判断。

原始每seed标签、预测、query0 attention和冲突分数见smoke.json。新增2项与已有检索3项共5项测试通过，tests.log。未运行无关训练/全仓库测试。

## 对“feel”设想的意义

支持把“当前目标影响读取哪项属性”写成明确接口。**没有测试从压缩表示解码细节、递归思考、持续状态学习或多模态feel。** 人工键已经把相关性答案编码进去，因此不能从72/72推出一般泛化、新颖性或优于普通cross-attention。

若继续，应让编码/属性读取从数据学习，保持对象与属性组合的独立测试，并加入普通attention和检索baseline；先验证held组合，再考虑接回持续Online状态，而不是直接删除tokenizer或历史。
