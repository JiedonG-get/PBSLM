# PBSLM 有界工作状态对照结果 v1

**当前 16 槽方案未达到继续投入门槛。** 在这个受控位置更新任务中，等容量精确字典逐题复现了槽位方案的读出和回答，峰值逻辑载荷只有它的约十二分之一。无界精确字典保留了全部已确认事实。调度器在提交前拦住了旧答案，但提交后的两次新回答都没有明确撤回旧说法。

基准和判据在 `e2d2e31` 冻结。执行代码与 seed 0 读出器在 `7710b78` 冻结。三组共享规则文本前端、八类位置、Qwen3-1.7B 后端及各自实验内的提示、解码与调度。输入只有截至该事件的可见文本，正确答案和题型仅用于评分。详见[冻结协议](BOUNDED_ONLINE_PROTOCOL_V1.md)。

## 快照结果

| 方案 | 主实验回答 /108 | 同生成器复验回答 /36 | 合计回答 /144 | 记忆读出 /144 | 主实验旧记录 /36 | 复验旧记录 /12 |
|---|---:|---:|---:|---:|---:|---:|
| 无界精确检索 | 96 | 36 | 132 | 144 | 32 | 12 |
| 16 条精确检索 | 73 | 27 | 100 | 108 | 9 | 3 |
| PBSLM 16 槽 | 73 | 27 | 100 | 108 | 9 | 3 |

三臂合计题型得分相同的部分为初答 11/12、更正 33/36、传闻 20/24、未知拒答 24/24。以每个已确认值的严格匹配计，无界组答对 108/120，其余两组各答对 76/120。完整反序复跑的 432 个记忆读出和 432 个模型原答逐项一致。

- 两个有界组的 36 个缺失读出全部是已确认的旧事实，均来自每流 `e44`、`e45` 和 `e59`。查询时目标已按最近写入顺序被淘汰。第一个旧记录查询 `e21` 在到达容量前完成，两个有界组均答对。整个基准中两个有界组的原始读出完全一致，未观察到槽位额外造成的错误值、误接受未知实体或额外缺失。
- 正确读出后的错答全部是 Qwen 弃答。两个有界组各有 8 题，无界组有 12 题，其中 4 题在有界组已丢失证据。由此，36 个读出差异在最终回答上表现为 32 个只由无界组答对的旧记录问题。比如 `bounded-online-05/e45` 的已确认位置是“澄光柜”，无界组读出该地点仍回答“不确定”。槽位组和容量匹配字典都未读出该事实。
- 这组等价性建立在同一实体的文本键保持一致、地点取自八类词表、确认标记由规则识别的条件下。样本未覆盖同一实体的别称、近义改写或来源冲突裁决。三条复验流共用文本模板，反序回放共用同一批题。

各臂处理 372 次确认写入与 144 次查询，均无额外模型维护调用。两个有界组各淘汰 108 次。字典载荷一律按 UTF-8 键长加每条 1 字节类标计算，遗漏 Python 对象和索引空间。槽位载荷来自整个 FP32 状态张量及冻结模块权重，遗漏临时张量与框架开销。固定模块含一个未用于槽位写入的标量。峰值是单条流的最大载荷。槽位满时为统计淘汰额外做一次匹配，记忆操作墙钟包含该检查。原始预测也保留进程 CPU 时间，当前运行的分辨率不足以稳定区分短字典操作。回放计时从创建记忆后开始，排除模型加载，受运行顺序、预热及共享机器负载影响。

## 调度与纠正

三组各执行相同的六个脚本场景。提交前使用宿主屏障，观测发生在首个 Qwen 工作线程作业的时间区间内，该区间包含提示构造与解码。每组的两个旧作业收到取消请求，随后仍在线程里运行至结束。九次屏障下的观察都到达于首个作业开始之后，六次更正从观察到旧作业释放约 118–379 毫秒。原始记录可复核作业、取消和提交时间。该设置只测整条回答提交，未记录逐 token 提交或 CUDA 内核起止。

| 每臂表现 | 无界精确 | 16 条精确 | PBSLM 16 槽 |
|---|---:|---:|---:|
| 提交前更正漏打断 /2 | 0 | 0 | 0 |
| 无关写入误打断 /1 | 0 | 0 | 0 |
| 被替换的旧回答提交 /2 | 0 | 0 | 0 |
| 提交前更正后的回答给出新值 /2 | 1 | 1 | 1 |
| 提交后更正的回答给出新值 /2 | 2 | 2 | 2 |
| 提交后明确撤回旧说法 /2 | 0 | 0 | 0 |
| 超容量冷读答对 /1 | 1 | 0 | 0 |

三组都正确读出了提交前更正后的“竹溪站”，Qwen 均提交“不确定。”。已提交后两个场景的原文分别是“江柳门。”随后“月湾站。”，以及“东练功房。”随后“松间厅。”。后一次推理的提示包含原回答，请求明确撤回旧说法。人工审查逐条提交，六次都只给出新地点。冷读中两个有界组都失去目标，无界组保留。每臂 10 次模型作业、8 次提交、0 次生成错误，包含两次被取消但执行至结束的作业。槽位与等容量字典各用 921 个输入、43 个输出 token。无界字典用 918 个输入、45 个输出 token。

## 门槛判定

| 预先冻结的判据 | 观察值 | 判定 |
|---|---|---|
| 相对无界对照整体落后最多 5 个百分点 | 主实验落后 21.3 点，复验落后 25.0 点 | 未通过 |
| 相对无界对照旧记录落后最多 10 个百分点 | 主实验落后 63.9 点，复验落后 75.0 点 | 未通过 |
| 相对等容量字典主实验至少提高 5 个百分点，或质量近似且总逻辑载荷至少降 25% | 准确率差为 0 点，峰值载荷约为 12.1 倍 | 未通过 |
| 相对等容量字典无额外漏打断、误打断和旧值误提交 | 三项差均为 0 | 通过 |
| 提交后两次更正同时给出新值并撤回旧说法 | 0/2 | 未通过 |

停止扩展本轮的 16 槽实现。保留精确检索作为持续运行对照。后续若继续研究，先把提交后纠正做成可验证的语义行为，并在有改写、实体别名和竞争事实的隐藏事件流上验证。下一种内部状态候选需要在给定资源下保住更多有用事实，或在同等质量下减少真实资源占用。本轮结论的范围是共享规则前端下的槽位方案，完整 PBSLM 语言架构仍需单独评估。

## 复现

从仓库根目录运行，使用空的输出路径。正式运行使用 Python 3.13.5、PyTorch 2.11.0+cu128、Transformers 4.51.0、RTX 4060 Laptop GPU 和本地 Qwen3-1.7B。模型文件 SHA-256、执行版本与源文件哈希见原始预测。使用同一个检查点目录并依次执行模型调用。

```bash
python -m evaluation.generate_bounded_online_v1 --output regenerated.jsonl
python -m evaluation.bounded_online_compare --model-dir /path/to/Qwen3-1.7B --fixtures regenerated.jsonl --output predictions.json
python -m evaluation.bounded_online_compare --model-dir /path/to/Qwen3-1.7B --fixtures regenerated.jsonl --reverse-arms --output repeat.json
python -m evaluation.score_bounded_online --fixtures regenerated.jsonl --predictions predictions.json --repeat repeat.json --output scores.json
python -m evaluation.bounded_online_repair --model-dir /path/to/Qwen3-1.7B --output repair.json
python -m unittest discover -s tests
```

槽位读出器从现有 `content_fast600/delta_seed0.pt` 导出为[有来源校验的 FP32 JSON](../../evaluation/fixtures/bounded_online_delta_seed0.json)。读取时对重建权重核验 SHA-256 `49312a6c239efec016af1bcc995d7b136c1c6c06af98d270be774fec72613b3c`，可直接使用，不需要重新训练。文本键取带固定域前缀的 SHA-256 摘要，将 32 个字节解释为 16 个小端有符号整数再转为 FP32，由原槽位模块归一化、作余弦匹配，阈值为 0.9。
