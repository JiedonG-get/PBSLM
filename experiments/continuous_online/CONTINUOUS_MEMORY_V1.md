四臂都答对了 3 条明确更正。检索与全历史总分相同，但答对的题不完全重合。检索比全历史少送入约 22.6% 的输入 token，它仍保留原文与索引，并在每次查找时扫描已存证据。最近窗口在全部 6 条旧记录保持题上都失分。递归摘要保留了其中 5 条，但 42 次笔记维护中有 5 次未在生成预算内产生 EOS、4 次触及字符裁剪。会议地点与物品交接等多实体问题中，仍可见把相邻对象的状态当成答案的错误。另两条公开开发流的得分依次为 4/6、5/6、5/6、3/6。

严格匹配只处理字符宽度、空白和句末标点。比如 `《微浪》` 与 `微浪` 会判为不同，报告保留原始答案供复核。服务时间是一次单 GPU、固定运行顺序下的模型调用累加，包含摘要维护。它未计算 Python 检索维护、峰值内存、排队或输入到输出的端到端延迟。

## 已提交输出的纠正探针

另用三个预先编写的场景测试已提交后的纠正。每次先等待初始回答提交，再送入一条由调用方标为无关的背景观察，最后送入更正并触发新回答。相同输入运行两次，分别给模型提供和隐藏先前已提交的回答。两组的运行器均保留原提交。

| 条件 | 首答给出原值 | 后答给出新值 | 明确说事实发生变更 | 明确撤回自己的旧说法 |
|---|---:|---:|---:|---:|
| 有已提交回答 | 3/3 | 3/3 | 1/3 | 0/3 |
| 隐藏已提交回答 | 3/3 | 3/3 | 1/3 | 0/3 |

人工按子句判定，并由另一位只读审阅者独立复核。检修场景两组都用“改到”或“改为”，表示外部计划变化。讲座和签收场景均直接说出新值，没有指明先前的话已失效。两组的签收首答均声称交接已经完成，初始信息并未确认这一点。有已提交回答组的纠正句也把新取件安排说成了已完成的签收。原值和新值列只统计值，完整语义结论以原文为准。

六次运行的原提交均保留，无关观察均没有启动生成。背景判定及开口由调用方控制，两个回答之间等待前一轮提交。本探针验证整句提交后的修正行为，尚无生成中途的语义续接结果。[原始输出与轨迹](qwen_postcommit_repair_v1.json)

```bash
python -m evaluation.qwen_postcommit_repair --model-dir /path/to/Qwen3-1.7B --output tmp/postcommit.json
```
