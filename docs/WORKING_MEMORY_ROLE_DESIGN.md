# 工作记忆结构候选：角色分离与有效性（下一项整合约束）

本文件是基于已测机制的设计约束，不是已实现的完整架构。用户目标为持续Online运行，M→A是慢速支线。

## 信息角色

- Query：当前需要解决的问题/表达目标，与观察片段分开，不能只靠拼接顺序隐含。
- Observation record：观察输入/显式反馈、来源、可比较的source epoch/sequence、有效/撤销状态。
- Retrieved evidence：由query对有效record检索得到，保存记录身份与分数；相似度不是可信度。
- Committed speech：已向外部提交的内容/版本，不能当作已经确认的世界事实回写。
- Consolidation candidate：由可靠且有效的记录选择出的慢更新目标，不能自动接受全部检索值。

## 已有证据对整合的约束

1. hard-all输入导致输出饥饿，background-all造成过时断言；观察版本和表达有效性边界必须区分。
2. 原始concat可以让前置问句主导原单实体读出；需要query/record接口，不能把所有字串当同一角色。
3. 常规nearest是强基线，soft attention提升很小；先复用标准检索，不宣称新算法。
4. E表示有跨表面作用但有限；更大随机绑定/新名字下明显失败，不能认为键空间已经普遍可靠。
5. 槽位替换/撤销可以精确改变保留约束，但会影响联合预测，不能承诺其他行为绝对不变。
6. 同source旧sequence不应覆盖新值，跨source不能直接比较sequence；来源自报不等于认证。
7. 累计/低秩统计已不可直接删除过时贡献，须与可撤销临时ledger职责分开。
8. 慢更新须隔离训练copy与live推理，需明示权重版本切换；目前没有安全并发内化实现。

## 下一项可检验整合

在固定权重的role-separated外部工作记忆里，先实现caller显式记录身份、source sequence和撤销。比较同query在新值确认、旧值迟到、来源冲突、撤销之后的检索记录身份/答案。所有无效记录不得只因高相似度被读出。

接口默认不猜entity slot/事实真假；来源冲突先返回未决，不用softmax平均掩盖。学习型抽取依旧是候选，不自动确认。

然后将该工作状态作为连续输入worker的快照给表达任务，验证相关更新失效与已提交内容保留；规则渲染与真实语言输出分开打分。只有这些因果/状态契约通过后，再尝试慢更新和更大语言范围。

## 不能以设计文件代替的证据

自然语言理解、自动relevance/说听策略、真实语义续连、电影音视频感知、长期总内存、生产持久化/鉴权和模型架构优越性仍未完成。
