# PBSLM 主线澄清：持续 Online 运行优先

用户明确：最原始、最主要目标是**持续在线运行**，Online Learning是可选增强，不是首要验收。

## 目标行为

- 输入持续到达，系统在输出期间仍接收/处理新信息。
- 新输入使旧判断过期时，及时停止未提交输出；保留已提交内容与必要上下文。
- 按最新上下文重新组织续接，而非盲目从旧token位置继续。
- 可以继续听、等待或开始表达；模型信心/一致性不自动等于应该说。
- 最终面向持续视频/声音/对白理解与交流，但本地原型尚没有这些感知能力。

## 近期可验证实现

固定权重，先做文本事件异步loop：输入revision、候选生成、提交fence、取消与续接；观测input-arrival/inference/commit/cancel时间。用确定性后端证明协议，再接真实PBSLM预测。

必须区分：

1. 接收输入不阻塞，与推理真正增量更新理解是两回事。
2. 取消Python任务/抑制过期提交，不等于抢占运行中的GPU kernel。
3. 流式显示已有字符串，不等于神经模型逐token实时生成。
4. 显式caller should_respond信号，不是模型自主学会选择说/静默。
5. 持久事件上下文传入backend，不代表当前小模型能理解长期上下文。

## 已有研究如何使用

保留A学习/M记忆/提取等正负证据，不删历史；但不再靠继续提高小型记忆分数来替代持续运行目标。未来训练、检索、M等实验只有在帮助持续状态、响应与稳定性时才作为支线推进。

## 下一步判据

- 生成进行中确有新输入到达；新revision后不再提交旧revision单位。
- 已提交前缀保留，新生成request收到该前缀与最新输入。
- 发生多次打断、wait模式和close仍不产生泄漏任务或过期输出。
- 真实模型推理不堵塞接收事件loop；延迟据实记录，不承诺硬实时。
- 报告实际backend能力边界，不宣布电影理解/Online Learning完成。
