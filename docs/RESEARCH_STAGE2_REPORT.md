# 第二阶段研究汇总：文本表面、反馈覆盖、提取风险与强基线

本报告对应用户“持续推进、逼近最终目标”的本次自主推进阶段。它不改写第一阶段报告，也不宣布完整研究/通用Online Learning完成。

## 从上一阶段推进了什么

1. 保存三份实际训练文本模型，strict加载检查词表映射、配置、有限tensor和clean M；模型只本地，GitHub公开hash、训练配置、曲线和来源。
2. 真实模型接入受限中文问句、反馈确认、有界slot覆盖/淘汰、中途fresh-model恢复；104事件×3seed。
3. 扩展到原精确库存之外的12种人工问法，冻结权重/词表，分开报告编码覆盖和接收后accuracy。
4. 单独训练陈述候选GRU reader，减少接口直接给字段；因held误接受风险，不开放自动写M。
5. 用独立校准表面选择接受policy，再测新的test表面；发现高经验precision不稳定迁移。
6. 补强有界控制器rollback/snapshot历史一致性，记录完整restore写成本。
7. 增加相同外部显式slot辅助下的普通字典强基线，验证高分是否真的需要矩阵读出。

## 现在能说什么

- 已形成可加载、小规模、同步的模型+记忆+确认协议原型。A学习、M写入、外部slot管理是不同机制，分别记录。
- 在熟悉词汇/实体格式、有限模板下，明确训练的键区分能改善换问法回忆；没有这个目标时出现绑定坍缩。
- 有界覆盖能避免同slot历史累加，但使用外部ledger和额外O(capacity)写入。精确slot问题上字典更简单且更准确；不能主张PBSLM更优。
- 候选抽取、记忆真实性和状态管理是三个不同环节。抽取reader会误判，置信度阈值没有跨表面安全保证，确认仍由外部负责。
- C不变证明稳定参照，不证明A旧知识保持；同步恢复通过不证明并发或崩溃一致性。

## 公开纠正的证据问题

- 原text_runtime报告误写102事件，已更正96+8=104，原JSON不覆盖。
- 原numerical_write_calls只计feedback，漏restore重建，已用只读脚本生成accounting_audit。含restore均值append104、bounded4 410、bounded8 776.3。
- 新pilot明确记录恢复前后M hash与同问题双份预测，旧结果只有assertion布尔值，不能追溯伪造细证据。
- 部分“打断”只提交JSON首字符，resume同观察，无并发新文本；报告明确不算语言token实时打断。
- 陈述reader的81.95%是seed宏平均，不是225/272的micro82.72%。
- 未见问法只是少数人工表面变换，compact库存预配置；不写成开放语言能力。

## 尚未解决的最终目标差距

1. 开放语言输入/多关系事实抽取、新实体识别、真实语料释义与时态否定泛化；当前reader不能安全自动确认。
2. 真值/来源认证、多来源冲突、延迟反馈、错误确认撤销；当前来源hash只追溯文字，不鉴真。
3. 长时间学习：目前最长104事件、小key库存；无自然语言长期保持、任务切换和held旧任务泛化证据。
4. 并发交互：没有GPU生成取消、流式token、输入重组织、延迟SLO、线程安全/多用户。
5. 资源优势：没有严格等FLOPs/存储字节的语言模型架构消融，字典强基线反而提示精确槽位应优先简单系统。
6. 审计/候选/观察历史仍无界，ledger有界不能称系统总内存有界。
7. checkpoint未上传且仍依赖本地训练重建；仅推理格式，不含optimizer/RNG恢复，不承诺bitwise跨GPU重跑。

## 下一阶段应以什么决定方向

- 先固定真实评估集和强检索baseline，明确神经机制究竟需要解决哪种软匹配/压缩/未知表面问题。
- 提取采用丰富难例+独立验证，并报告风险/覆盖和人工确认工作量；不因阈值高就开放自动写入。
- 在同样语义辅助与容量下比较字典、向量检索、矩阵M；只有实际额外收益才承担复杂度。
- Runtime推进真正token级并发前，先隔离版本切换/参数更新与推理，保存可恢复状态和撤销协议。

这次完成的是可检验的研究阶段与原型，不是终点。最重要的收益是把“有希望”变成具体可证伪的机制假设，并保留了字典基线和提取失败等不利证据。
