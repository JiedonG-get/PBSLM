# ONLINE — Online / 半在线学习设计

本文件是设计意图，不是当前已实现状态。Phase 1 的 v2.1 baseline 还没有 online 训练。

## 1. 为什么要 online

离线预训练后，模型不会把新经历写入长期状态；每次新数据都要重训会破坏已学表示。
PBSLM 的方向是：

- **A 侧在线更新**：让 A 路径在交互中适应新信息；
- **C / 主块 / InfoFlow 冻结**：保留稳定的基准与已学表示；
- **E 块 + 记忆 M 持续写入**：让经历以关联记忆形式积累，而不是直接改所有参数。

这就是「半在线」：不是所有参数都在线，而是只让 A 侧和 E/记忆通路更新。

## 2. 参数分组（设计）

| 分组 | 在线时状态 | 理由 |
|---|---|---|
| A 侧角色/解码器部分 | 可更新（小学习率） | 适应新任务/新分布 |
| E 块 + 记忆写入 | 可更新 | 积累经历 |
| C 路径 | 冻结 | 保持基准判断 |
| BlockBank 主块 | 冻结 | 避免灾难性遗忘 |
| InfoFlow | 冻结 | 保持一致性度量稳定 |

具体参数清单需要在 `model_v2.py` 中显式列出，并用单元测试保证没有漏网/误冻结。

## 3. 记忆写入的时间因果

写入 value 必须来自**当时可获得的信息**：

- 离线 teacher forcing 时可以用目标 token 的码本做写入；
- 在线推理时还没有目标 token，只能用**预测/commit 后的 token**，或延迟到反馈到达再写；
- 不能用「未来 token」写入，否则评测会泄漏。

当前 v2 代码的 `write_memory` 仍是离线调试用法，正式 online 前需要重做接口。

## 4. Online 的验收

- 在线阶段前后：held 指标不能大幅退化；
- 记忆增益：`M 正常写入` vs `M 恒零` vs `打乱写入 value` 三组对照；
- 在线更新后旧任务保持（无灾难性遗忘）；
- 记忆容量/遗忘曲线可解释（不是范数越大越好）。

## 5. 与 Phase 的关系

| Phase | 内容 |
|---|---|
| Phase 1 | 离线 baseline（已完成） |
| Phase 2 | A/C、Flow、E/M、PerturbField 消融 |
| Phase 3（计划） | Online：冻结/更新分组、记忆写入因果、持续学习评估 |

在 Phase 2 没有证明 E/M 有增益之前，不做 Online；否则只是在给一个未验证的模块加复杂度。
