# 内部状态优先研究阶段：结果、代价与下一步

用户新方向：优先靠模型自身状态持续理解，需要时才访问外部记忆；允许根本改结构但不偏离持续Online。此阶段保留原PBSLM与全部历史记录，没有执行删除。

## 完成的机制工作

- M→A隔离：教师M可影响学生M-off参数，但原O1在小任务有遗忘/换表面差；hard/soft目标对照未解决。
- 冻结E读出：显式已训练键表示比部分简单特征更有迁移，但多批仍遗忘，容量扩大后失效，不能外推语言能力。
- 累计统计、可替换约束、低秩压缩：拆开历史保留/求解器/泛化，明确额外存储与失效撤销边界。
- 角色分离：query/record/value标准检索，避免无标记concat猜目标；仍由caller提供角色/反馈，非自主语言理解。
- 全局GRU96float查询无历史：384步约54.7%，屏蔽h接近随机，固定state有用但不可靠。
- 学习型分槽同96float：384均匀流约97%，但8192次hot写后cold仅18.2%；短高分不等于长期保持。
- 同权重写门控干预：稀疏写减少旁路干扰，全部hotID检验揭示共享slot覆盖与热ID退化。
- 匹配稀疏训练：all-hot冷保持约92.6%，加known-ID碰撞prior约96.9%；残余碰撞仍失败，不是动态分配。
- 触发基线与观察字典回放：guard标记碰撞，容量足够时能补错误，但需要全部写入维护且未测整体算力。

## 可据以保留的结构方向

1. 明确当前query/观察/表达角色，不依赖无标记拼接。
2. 选择性写入与可追溯有效状态，避免soft更新无关记录长期衰减。
3. 寻址/分配可靠性与更新隔离分开测，不能只硬化top1忽略碰撞。
4. 状态优先须有错误/拒答/回退策略，同时记录coverage与维护成本。
5. 慢内化须保留可靠旧约束并支持来源/纠正，不能把检索到的值照单写进A。

## 还没有完成的目标

- PBSLM主模型集成上述状态候选，真实连续语义理解与流畅语言输出。
- 动态未知身份分配、新关系、语言实体抽取/角色理解；当前多为8ID任务。
- 可信置信度/独立验证集选择fallback，真实live检索与省算力证据。
- 持续音视频感知、自然打断续连、自主说听policy；此前Runtime仅提供机制基础。
- 长期总资源/崩溃恢复/跨设备状态/可撤销长期内化。

## 为什么不继续在小任务调分

小测试已经找到实际问题：类别偏移、表示目标混淆、顺序约束损失、旁路写泄漏与slot碰撞。但没有基本语言能力时，小状态满分不能变成电影理解。下一阶段需要固定真实或更丰富事件集与强语言/检索baseline，单独预算模型/数据规模。

## 下一阶段建议顺序

- 第一：动态key输入与有限slot分配、覆盖/拒答，不把entity ID→slot静态查表当泛化。
- 第二：将候选作为独立state module接入既有ContinuousRunner，区分观察更新和输出取消，真实记录fallback调用与耗时。
- 第三：有基本语言能力的固定后端或受控预训练规模，评估标注短故事dev/独立test；同流评分当前状态、语义续连、误/漏打断和表达进展。
- 第四：可靠状态经版本化慢更新进入A，保留旧任务与错误撤销验收。

本阶段是机制与结构候选筛查，不是最终系统完成。当前goal应保留未完成；自动轮次到限不构成研究成功或真正阻塞。
