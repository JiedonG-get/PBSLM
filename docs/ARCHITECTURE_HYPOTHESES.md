# 结构修改候选与淘汰条件（尚未实现）

本文件把用户授权的结构修改约束到可验证假设，不能当作已完成架构。

## H1：快速工作状态与慢参数必须分离

当前矩阵M对同key累加，外部重建可纠正但成本高。候选：独立工作状态保存可撤销的key/value、source revision、有效状态；A只读取快照，不因每条观察立刻改参数。比较矩阵M、精确字典、向量检索；相同容量与语义辅助，分别报告检索/软匹配/来源覆盖和延迟。

淘汰条件：若神经机制在新表面/噪声/压缩预算下没有比简单检索多出可复核收益，保持简单状态方案，不为结构复杂而复杂。

## H2：现有O1慢更新缺少稳定性与可迁移表示

第一批内化显示训练表面可学、held弱、无回放旧事实丢失。当前任务还含旧新label分布不重叠混杂，未证明是架构根因。下一实验应先soft teacher/zero teacher、共享答案类别、相同样本与预算，区分监督信息和表示瓶颈。

结构候选：在冻结底座上加入可隔离、可版本化的慢adapter，或允许受控表示学习；与原O1、扩大同样参数量、回放baseline比较。teacher固定、student M-off、held模板/旧能力/episodic能力都必须测。

淘汰条件：只有训练样本提高而held/旧能力没有改善，不接受“成功内化泛化”的结论。

## H3：观察处理与表达状态需要不同版本

原hard-all让输入高速变化时输出饥饿；显式无关背景能允许表达，但依赖caller。候选：持续观察状态与回答依赖快照分离，相关证据改变时只失效受影响表达；表达过程中反向维护已说承诺，必要时明确修正而非拼接。

先用标注短故事验证相关性/断言时效/已说内容关系，再考虑学习型gate。不可通过全部background或人为减少输入掩盖困难。

淘汰条件：漏打断导致过时断言增加，不能以输出更多抵消；规则oracle成功也不代表模型自主理解。

## 规模升级条件

小规模用于筛机制和调错；达到同表面以外的迁移与保持信号后，需要有基本语言能力的中等规模模型/真实文本，否则不能判断一般语言效果。训练与推理数据/预算/参数数必须记录，不能把预训练能力差误判为Online架构失败。

所有候选单独版本与实验目录，原PBSLM/checkpoint/日志保留。慢内化不在现live Runtime里无锁更新，未来必须有权重版本切换与rollback规范。
