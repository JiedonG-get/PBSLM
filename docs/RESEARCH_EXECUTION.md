# PBSLM 研究推进与完成标准

2026-11-15 用户授权继续推进整个研究，分阶段实施并及时上传 GitHub。本文是接手后的工作边界，不改写历史实验。

## 研究问题

在稳定参照 C、可适应路径 A、记忆 M 分离的架构中，能否通过受控在线经验改善新任务表现，同时保留旧能力？并行块与 InfoFlow 是否带来独立于计算预算的收益？

研究可以完成一组可复核实验与明确的正/负结论，不能保证假设成立或把有限实验当作通用智能证明。

## 推进顺序

1. **工程证据闭合**：端到端逐样本 M1 与批量 M2 按物理块对齐；双侧路由变化；NaN 与非退化梯度 probe；真实本地 checkpoint 的原始/迁移加载。保存原始结果和适用条件。
2. **小规模学习基线**：固定数据、预算、初始化，验证码本对照与 A/C 预测、互补性。先做成本测量，再选择预算；不扩大模型掩盖问题。
3. **最小持续适应实验**：predict-before-learn 的时间序列；只有观察到答案/反馈才更新；A-only、M-only、二者组合、无更新、打乱记忆等对照。分离学习收益、记忆收益与数据泄漏。
4. **保持性与失败机制**：旧任务固定集、C 同输入输出不变、A 遗忘量、反复切换任务、记忆污染/擦除，至少多个 seed。学习收益与旧能力保持分别报告。
5. **Runtime 验证**：输入、候选、输出提交、打断、恢复和 snapshot 的状态契约；先用确定性模拟验证，不把状态机能运行称作学习成功。
6. **研究总结**：合并证据与负结果，标明可复现范围、计算预算、未验证假设；同步 README 与研究报告。

## 纪律

- Phase 1 原始 logs/metrics/checkpoints 不覆盖；后续实验放独立目录。
- 默认 legacy 路径和参数结构保持；行为修订必须解释并回归。
- 不将 agreement 当置信度；不把 C 不变当作 A 没遗忘。
- 共享只读块表示不是自动泄漏；共享参数更新则会影响两侧，必须冻结或量化。
- 先提交可复核的小阶段，不反复等待用户转发审查来代替执行。
- Git 正常 fetch/push 已恢复；本地旧 API 提交史保留在 archive/local-before-gpt，当前 main 对齐远程同内容历史。
- 不向第三方代理发送 GitHub 凭据；后续优先使用 origin 的正常 Git 认证连接。
